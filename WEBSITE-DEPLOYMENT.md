# Website Deployment Guide

## Overview
This guide explains how to deploy the 2nd Tolworth Scouts website to AWS S3 for static hosting.

## S3 Bucket Setup

The website uses the same S3 bucket (`2ndtolworth`) that stores the calendar JSON files generated by the Lambda function.

### One-Time Setup

1. **Update IAM Policy** (if needed)
   
   The `vsstudio` user needs permissions for S3 website hosting. Update the policy with:
   ```bash
   # Policy file: /home/windsor/github/lambdas/scouts/vsstudio-website-policy.json
   # Upload this via AWS Console: IAM → Users → vsstudio → Permissions → Edit policy
   ```

2. **Configure S3 Bucket for Static Website Hosting**
   
   ```bash
   cd /home/windsor/github/scouts
   ./setup-website-hosting.sh
   ```
   
   This script:
   - Enables static website hosting on the bucket
   - Sets `index.html` as the index document
   - Allows public access to the bucket
   - Sets a bucket policy for public read access

## Deployment Methods

### Method 1: GitHub Actions (Automated)

The website automatically deploys when you push to the `master` branch.

**Setup GitHub OIDC and repository configuration:**
1. Go to your GitHub repository: `antonio1000homens/nfc`
2. Navigate to Settings → Secrets and variables → Actions → Variables
3. Add `AWS_ROLE_TO_ASSUME` with the IAM role ARN GitHub should assume for deployment
4. Ensure the IAM role trust policy allows GitHub OIDC (`token.actions.githubusercontent.com`) for this repository
5. Keep the CloudFront distribution ID in Bitwarden and set `BW_CLOUDFRONT_DISTRIBUTION_ID` as a GitHub Actions variable if you want automatic invalidation

**Workflow File:** `.github/workflows/deploy-to-s3.yml`

The workflow:
- Triggers on push to `master` branch or manual dispatch
- Assumes an AWS IAM role via GitHub OIDC
- Configures S3 bucket for static website hosting
- Sets bucket policy for public read access
- Syncs HTML, CSS, JS, fonts, images to S3
- Applies cache control headers

**Manual Trigger:**
1. Go to Actions tab in GitHub
2. Select "Deploy Website to S3" workflow
3. Click "Run workflow"

### Method 2: Manual Deployment (CLI)

Deploy from your local machine:

```bash
cd /home/windsor/github/scouts
./deploy-website.sh
```

This script removes any legacy top-level folders (e.g. `/beavers`, `/badges`) before syncing the current `website/` content and root `index.html`.

## Access the Website

**Website URL:**
```
http://2ndtolworth.s3-website.eu-west-2.amazonaws.com
```

The website will:
- Load calendar events from `agenda.json` (generated by Lambda)
- Load programme items from `programme.json` (generated by Lambda)
- Display scout information and resources

## Cache Control

All files are deployed with cache control header:
```
Cache-Control: public, max-age=3600
```

This means browsers will cache files for 1 hour. To invalidate cache, users can hard refresh (Ctrl+Shift+R).

## Updating the Website

1. **Make changes** to HTML, CSS, or JS files in the `scouts` directory
2. **Commit and push** to the `master` branch:
   ```bash
   git add .
   git commit -m "Update website content"
   git push origin main
   ```
3. **GitHub Action runs automatically** and deploys changes
4. **Check deployment** in GitHub Actions tab

Alternatively, use manual deployment:
```bash
./deploy-website.sh
```

## Troubleshooting

### Check Bucket Policy
```bash
aws s3api get-bucket-policy --bucket 2ndtolworth
```

### Check Website Configuration
```bash
aws s3api get-bucket-website --bucket 2ndtolworth
```

### List Deployed Files
```bash
aws s3 ls s3://2ndtolworth/ --recursive
```

### Test Website Access
```bash
curl -I http://2ndtolworth.s3-website.eu-west-2.amazonaws.com
```

### View GitHub Action Logs
1. Go to repository → Actions tab
2. Click on the latest workflow run
3. Click on "deploy" job to see detailed logs

## Security Notes

- The bucket allows **public read access** for website files
- Calendar JSON files are also publicly accessible
- No sensitive data should be stored in this bucket
- The Lambda function has separate permissions to write to the bucket

## Cost Considerations

S3 static website hosting costs:
- **Storage**: ~$0.023 per GB/month
- **Data transfer**: First 1 GB free, then ~$0.09 per GB
- **Requests**: Minimal cost for GET requests

Expected monthly cost: < $1 for this small website.
