Technical documentation

This section documents how event enrichment moves from the Scouts scheduler through SQS, Step Functions, the enrichment worker, DynamoDB safety state, and the configured AI providers.

View enrichment sequence

Orchestration

scouts-full-enrich is the authoritative normal-path workflow for tagline, image theme, and image generation.

Transport

scoutsRequests carries ingress and callback stage messages; scoutsProcessing carries worker jobs.

Safety state

DynamoDB owns per-HEX/per-stage attempts, cooldowns, leases, idempotency, cached results, and quarantine.

Providers

Gemini handles text enrichment. Image generation is explicitly selected as Cloudflare or Gemini, with no automatic provider fallback.

Enrichment flow

flowchart LR
    A[scouts Lambda\nscan / reconciliation] -->|scoutsRequest new / retry| Q1[(SQS scoutsRequests)]
    Q1 --> B[scouts2sqs\nfull-enrich adapter]
    B -->|StartExecution| SF[Step Functions\nscouts-full-enrich]

    SF -->|waitForTaskToken\ntagline / imageTheme / image| Q1
    Q1 --> B
    B -->|translate callback stage| Q2[(SQS scoutsProcessing)]
    Q2 --> W[sqs2scouts\nfull-enrich adapter]

    W --> D[(DynamoDB\nscouts-enrichment-state)]
    W --> U[(DynamoDB\nusage counters)]
    W -->|tagline + imageTheme| G[Gemini text]
    W -->|image, provider=cloudflare| C[Cloudflare Workers AI]
    W -->|image, provider=gemini| GI[Gemini image]
    W --> S3[(S3 events + images)]
    W -->|SendTaskSuccess / SendTaskFailure| SF

    D -. cooldown / quarantine / cache .-> W
    S3 -. persisted event state .-> A
Key hand-off: Step Functions does not call the AI provider directly. It sends a callback task to scoutsRequests; scouts2sqs translates that task and places it on scoutsProcessing; sqs2scouts owns the external provider call and sends the task-token callback.

The workflow determines the first missing stage when it starts, so partially enriched events do not regenerate fields that already exist.

Retry, idempotency and cost controls

  • State key: HEX + stage.
  • Maximum automatic attempts per stage: 3.
  • Cooldowns: 1 hour after the first failed attempt, then 6 hours after the second.
  • After the third failed attempt, or a permanent configuration/authentication error, the stage enters manual_review.
  • An in_progress lease prevents concurrent deliveries from both calling a provider.
  • Successful provider output is cached before downstream event persistence; a later S3 failure retries persistence rather than generation.
  • Daily image/provider budgets are reserved only after the worker wins the stage reservation.
  • Provider/global quota deferrals do not consume a per-event attempt.

Provider selection

IMAGE_GENERATION_PROVIDER=cloudflare | gemini | disabled
IMAGE_GENERATION_DAILY_REQUEST_LIMIT=10
CLOUDFLARE_AI_MODEL=@cf/black-forest-labs/flux-1-schnell
CLOUDFLARE_AI_STEPS=4

When Cloudflare is selected, a Cloudflare failure does not automatically fall back to Gemini. This prevents an unexpected provider failure from turning into paid Gemini image usage.

Operational troubleshooting

SymptomCheck
No full-enrich execution startsscouts2sqs logs, full-enrich ARN, states:ListExecutions/StartExecution, and current image-provider setting.
Execution waits on a stagescoutsRequests, then scoutsProcessing, then the sqs2scouts callback logs.
Repeated event is skippedDynamoDB state for the relevant HEX + stage: in_progress, retry_wait, succeeded, or manual_review.
Provider succeeded but event is incompleteLook for persist_pending; the cached result should be reused without another provider request.
Image generation stopped for the dayUsage counters, provider quota state, and nextRetryAt.
