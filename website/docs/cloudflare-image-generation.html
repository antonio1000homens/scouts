Cloudflare Workers AI image generation

Gemini remains the text provider for tagline and imageTheme. The image stage can use Cloudflare Workers AI FLUX.1 Schnell with explicit billing-safety controls and no automatic Gemini image fallback.

Target configuration

GEMINI=true
GEMINI_IMAGES=false
IMAGE_GENERATION_PROVIDER=cloudflare
IMAGE_GENERATION_DAILY_REQUEST_LIMIT=10
CLOUDFLARE_AI_MODEL=@cf/black-forest-labs/flux-1-schnell
CLOUDFLARE_AI_STEPS=4

IMAGE_GENERATION_PROVIDER=disabled is the fail-closed default and makes no external image-generation call.

Request path

flowchart LR
    SF[Step Functions image callback] --> Q1[(scoutsRequests)]
    Q1 --> S2S[scouts2sqs]
    S2S --> Q2[(scoutsProcessing)]
    Q2 --> W[sqs2scouts]
    W --> D[(DynamoDB retry/idempotency)]
    W --> U[(DynamoDB image usage/circuit)]
    W --> CF[Cloudflare Workers AI REST]
    CF --> W
    W --> D
    W --> S3[(S3 image + event JSON)]
    W --> SF

The worker wins the HEX + image conditional reservation before it consumes application image budget or calls Cloudflare. Duplicate SQS deliveries therefore do not consume another inference.

Credentials

CLOUDFLARE_ACCOUNT_ID=<account-id>
CLOUDFLARE_AI_API_TOKEN_PARAMETER=/scouts/sqs2scouts/cloudflare-ai-api-token

The token is stored as an SSM Parameter Store SecureString. Only the parameter path is exposed to Lambda/CloudFormation.

Use a least-privilege Cloudflare API token that can invoke Workers AI for the configured account. Do not use a Cloudflare Global API Key.

Free-plan and billing safety

Do not enable automatic Gemini image fallback. It would turn a Cloudflare failure into potentially billable Gemini image usage and defeat the purpose of this migration.

The design assumes the Cloudflare account remains on Workers Free. If the account is upgraded to Workers Paid, usage above the included allocation can become billable, so the application keeps an independent daily image request cap.

The default cap is 10 external image inference attempts per UTC day. Cached-result reuse, persistence-only retries and duplicate SQS deliveries do not consume the cap.

Durable retry reuse

After Cloudflare returns an image, the worker normalises it with Sharp and caches the bounded JPEG in the enrichment-state record before final S3/event persistence.

Cloudflare succeeds
→ cache generated JPEG + generationId
→ write image/event to S3

If S3 fails:
next delivery → reuse cached JPEG → retry persistence only → no Cloudflare call

Safe rollout

  1. Deploy with IMAGE_GENERATION_PROVIDER=disabled.
  2. Confirm existing Gemini text enrichment still works.
  3. Configure the least-privilege Workers AI token in SSM.
  4. Set IMAGE_GENERATION_PROVIDER=cloudflare and keep GEMINI_IMAGES=false.
  5. Generate one known image and confirm one Cloudflare inference plus the expected S3 update.
  6. Repeat the same generation and confirm cached reuse with zero additional inference.
  7. Force persistence failure after generation and confirm the cached JPEG is reused.
  8. Verify Gemini Images receives zero calls and Cloudflare usage stays within the intended Free allocation.

Rollback

To stop all image generation:

IMAGE_GENERATION_PROVIDER=disabled
GEMINI_IMAGES=false

To explicitly restore Gemini image generation for a controlled rollback where paid use is intentionally accepted:

IMAGE_GENERATION_PROVIDER=gemini
GEMINI_IMAGES=true

Rollback is never automatic.
